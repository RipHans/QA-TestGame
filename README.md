# TestGame: QA тестовое задание
Это тестовое задание на позицию QA engineer. Тестирование слот-игры Testgame.

## Что проверялось
- Логика начисления выигрыша по PAYTABLE,
- Соответствие UI ответам сервера,
- Соответствие мобильной и ПК версии сайта, 
- Протокол websocket(START_GAME/END_FEATURE/END_GAME),
- UI/визуальная frontend логика,
- UX/gamefeel
- Поведение приложения при нестандартном использовании

## Структура

```
.
├── model_logic.py           # Отвечает за главную логику проверки выигрыша
├── main.py                  # Парсит нужные данные в лайв режиме, записывает лог
├── parser.py                # Парсит данные из пришедшего фрейма веб-сокета
├── logger.py                # Пишет логи сессии в файл (папка /attachments/logs)
├── test_model.py            # Проверяет логику слотов на тестовых данных через pytest
├── analyze_har.py           # Черновик, служит для анализа сохраненной сесси HAR из DevTools (можете сохранить в файл session.har в этой же директориии и протестировать, если интересно)
├── attachments/
│   ├── json/                # ответы сервера GET_PAYTABLE_INFO, GET_DYNAMIC_HELP_INFO и т.д.
│   ├── screenshots/         # скриншоты интерфейса, правил, paytable
│   └── logs/                # логи прогонов трафика через модель для сравнения с ответами сервера.
├── bugs/                    # Папка с Bug Reports
│   ├── critical/
│   ├── high/
│   ├── medium/
│   └── light/
├── README.md                # Вы здесь :)
└── requirements.txt         # Зависимости для запуска pytest и playwright
```

## Как запустить тесты:

### Установка
```bash
python -m venv .venv

.venv\Scripts\activate.bat          (для windows)

pip install -r requirements.txt     (зависимости)

playwright install                  (браузер playwright)
```

### Тесты логики (без браузера)
```bash
pytest -v
```
### Автомтический сбор данных о спинах, проверка на валидность согласно правилу "or from the rightmost", записть логов
```bash
python main.py                      (-r -m, --no-headless)

-r или --rounds *кол-во раундов*    (default=100, флаг для указания клоличества раундов, которые нужно пройти)
-m или --mismatches                 (флаг для запими только расхождений)
--no-headless                       (флаг для запуска в оконном режиме)

```

## Открытые вопросы
- RTP около 500% на 2000 раундах вместо заявленных 96.01%. Оформил как критический баг - если это тоже часть задания. Если же особенность специально внедрена чтобы у кандидатов баланс не падал до нуля, то поведение багом не является. (См. Примечания в баг-репорте)
- Незивестный модификатор scatter для винограда (в правилах не описано). Оформил как баг с низкой критичностью. Возможно им не является. (См. Примечания в баг-репорте)
- Если логика кнопки STOP задумываласть только для остановки режима AUTO, [BUG-009](/bugs/medium/BUG-009-stop-not-working.md) можно не рассматривать, он не является багом.
- В ПК версии время отображается только в полноэкранном режиме, оформлять как баг не стал, прошу уточнить задуманную логику.


## Заметки
- Адрес игры (в поисковой строке) содержит debug=true, в консоль выводятся баланс, ставка и состояние раунда
- При клике на кнопку выключения (правый верхний угол) происходит
  переадресация на https://gametests.nyc.wf/organic/standalone/ (403 Forbidden).
  Предполагаю, что страница закрыта администратором намеренно, так как её
  функционал не входит в тестовое задание. Баг-репорт не создал.
- Минимальный доступный номинал (COIN VALUE) = $0.001 (одна десятая цента).
  Подтверждается в ответе сервера `GET_PAYTABLE_INFO` (`denoms_set` от 0.001), и в
  интерфейсе, значение действительно выбирается. С одной стороны кажется что это неправильно, так как одна десятая цента нигде не встречалась, но с другой стороны возможно (гипотетически) что в дальнейшем добавятся другие валюты, мельче доллара и тогда это пригодится.  Баг-репорт не создал.
- При изменении размера окна на десктопе (или через DevTools) интерфейс масштабируется пропорционально, но не переключается на  мобильную верстку, режим валюты недоступен, несмотря на то что по ширине окно соответствует мобильному. Не могу проверить на реальном мобильном устройстве, так как там нет доступа к консоли. Баг это или особенность архитектуры не понятно. Так как на мобильном устройстве есть своя верстка - баг-репорт не создал.

## Ограничения тестирования
Не провено поведение игры/выплат, когда все барабаны заполнены виноградом/колокольчиками/звездами/семёрками (удваивается ли выигрыш как с вишней и сливой).
Свежая сессия с балансом 10 000 и coin value=1$ используется скриптом по умолчанию. Если изменть denom вручную в оконном режиме, то RTP будет считаться не верно.
